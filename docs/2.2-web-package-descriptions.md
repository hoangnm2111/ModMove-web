## Package descriptions

| No | Package | Description |
|----|---------|-------------|
| 01 | app (src root: main.tsx, App.tsx, index.css) | **Description:** Entry point of the SPA (React 18 + Vite + TypeScript). main.tsx mounts `<App />` in StrictMode and loads index.css (Tailwind). App.tsx wraps the app in BrowserRouter, renders AppRoutes and the global ToastViewport / ConfirmHost, and imports `services` once to register business handlers (cancellation refund, wallet settlement).<br>**Naming Conventions:** Only main.tsx and App.tsx, no business logic. Import alias `@/` points to `src/`. |
| 02 | routes | **Description:** Route table and guards. AppRoutes lazy-loads every page with `React.lazy` + Suspense and groups routes by role; guards: RequireRole (signed-in + role check, redirects to `/login?redirect=…`), GuestOnly, GuestOrCustomer (guest can draft a booking) and Fallback (redirect to the role's home via `getRoleHomePath`).<br>**Naming Conventions:** One file AppRoutes.tsx; guard components in PascalCase named by rule (Require<Rule>, <Who>Only). URLs follow `/<role>/<screen>` (e.g., /driver/jobs, /dispatcher/live-map, /admin/dashboard). |
| 03 | layouts | **Description:** Page frames per role (header, sidebar/tab bar, `<Outlet />`). DriverLayout also hosts the JobAlertModal from features/driver.<br>**Naming Conventions:** `<Role>Layout.tsx` exporting `<Role>Layout` (CustomerLayout, DriverLayout, DispatcherLayout, AdminLayout). |
| 04 | pages | **Description:** One component per screen, grouped by area: landing, auth, account, customer, driver, dispatcher, admin. Pages compose features and components and read data through hooks/services.<br>**Naming Conventions:** `pages/<area>/<Name>Page.tsx` with a named export (e.g., customer/BookingPage.tsx, customer/LiveTrackingPage.tsx, driver/DriverJobListPage.tsx, dispatcher/LiveMapPage.tsx, admin/DriverApprovalPage.tsx). Role-specific pages are prefixed with the role (Driver…, Admin…, Dispatcher…). |
| 05 | features | **Description:** Feature-specific UI and logic reused by several pages: booking (4-step wizard: RouteStep, CargoStep, VehicleStep, PaymentStep; AddressInput, FareSummary, bookingValidation), orders (OrderActionModals), payment (PayOsModal), driver (JobAlertModal, useAcceptJob).<br>**Naming Conventions:** `features/<feature>/`; components in PascalCase .tsx, hooks `use<Name>.ts`, helpers camelCase .ts; wizard steps `steps/<Name>Step.tsx`. |
| 06 | components | **Description:** Shared presentational components without business state: Button, Badge, RouteMap, MapPlaceholder, SuspenseOutlet; primitives in components/ui: Field, Modal, PhotoUploader, StatusBadge, feedback (Toast, Confirm).<br>**Naming Conventions:** One component per file, PascalCase file and named export (e.g., Button.tsx → Button); styling with Tailwind classes merged by clsx / tailwind-merge. |
| 07 | hooks | **Description:** Custom React hooks that subscribe UI to data: useLiveData (read + subscribe, useAction, useCountdown), useDomainData (useCustomerOrders, useOrder, useAvailableJobs, useDriverWallet, useIncidents, …), useDriverContext.<br>**Naming Conventions:** `use<Name>.ts`, each exported function starts with `use`. |
| 08 | store | **Description:** Client state with Zustand: session and active role (useAuthStore), booking draft kept across wizard steps (useBookingDraftStore), driver UI state (useDriverStore).<br>**Naming Conventions:** `use<Name>Store.ts` exporting a hook `use<Name>Store` created with `create<State>()`; helper selectors as plain functions (e.g., getRoleHomePath). |
| 09 | services | **Description:** The only package that reaches data sources. api.ts creates the Axios `apiClient` (base URL `VITE_API_BASE_URL`, Bearer token interceptor, logout on 401) for the ASP.NET Core API; module services (auth, order, catalog, map, case, wallet, driver) expose async functions plus `subscribe` for live updates. Until the API is integrated, they run on services/mock/storage (seed data persisted in localStorage).<br>**Naming Conventions:** `<module>.service.ts` exporting an object `<module>Service` with verb-noun methods (e.g., orderService.listAvailableJobsSync, orderService.subscribe); errors as ServiceError; index.ts is the barrel. |
| 10 | domain | **Description:** Pure business rules with no React or I/O: pricing (calculateFare, calculateCommission, validateCoupon), orderRules (status transitions, cancel/refund/rating rules), validators (phone, email, password, photo file), vehicleFit, geo (haversineKm).<br>**Naming Conventions:** camelCase files named by rule area; functions are verbs or predicates (calculate…, validate…, can…, is…, has…). |
| 11 | types / constants / config / utils / assets | **Description:** Shared kernel used by every package: TypeScript types matching backend DTOs (order.types, user.types, case.types); constants (status labels, MESSAGES MSGxx from SRS); config/business.ts (business parameters, PayOS receiver, IS_DEMO); utils/format.ts (formatCurrency, formatDate); static images in public/images.<br>**Naming Conventions:** Types `<module>.types.ts` with PascalCase types (ShippingOrder, UserRole, OrderStatus); constants in UPPER_SNAKE_CASE (ORDER_STATUS_CONFIG, MESSAGES, BUSINESS); utils as camelCase functions. |
